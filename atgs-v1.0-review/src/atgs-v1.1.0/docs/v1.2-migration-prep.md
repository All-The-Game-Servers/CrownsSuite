# ATGS v1.2 Migration Prep Notes

This document exists so v1.1 can prepare the codebase for the later multi-tenant refactor without partially implementing that refactor early.

## What v1.1 deliberately does

- keeps the current single-tenant operator model
- improves observability and recovery surfaces
- persists more operator-facing metadata, such as keeper resource snapshots
- stabilizes the current APIs consumed by Progenitor

## What v1.1 deliberately does not do

- no workspace or tenant ownership model
- no end-user accounts
- no subscription or billing data model
- no partial impersonation or support shell surface

## Areas to isolate before v1.2

1. Keeper identity assumptions
   - current APIs still assume a single global operator can see every keeper
   - future work should gate keeper visibility through ownership or membership rather than changing the transport model

2. Instance ownership assumptions
   - current instance APIs are global and operator-facing
   - v1.2 should add workspace-aware listing and mutation without breaking the current Progenitor client contract during migration

3. Route metadata
   - route state is now explicit in instance views for Java and Bedrock
   - v1.2 should preserve this route contract even if ownership and UI scopes change

4. Backup and recovery metadata
   - backup and schedule APIs now expose enough operator state to remain stable during a user-model migration
   - avoid coupling restore or retention logic to the future account model

## Upgrade guidance

- migrate database schema forward before moving users onto a v1.2 build
- validate Progenitor against a staging Central after any ownership-model migration
- preserve instance IDs, keeper IDs, route assignments, and backup IDs as stable identifiers across the migration
