# ATGS v1.2 Migration Notes

v1.2 is no longer just prep. The workspace-first foundation now exists in the codebase and upgrades pre-v1.2 installs into one default workspace.

## What lands in v1.2

- `workspaces`, `workspace_memberships`, and mocked workspace subscription state
- workspace ownership on keepers, instances, backups, schedules, and enrollment tokens
- a default-workspace migration that preserves existing stable IDs
- workspace-aware human API routes under `/api/v1/client/...`
- bounded remote file-management task kinds scoped to each instance data root

## What is still intentionally out

- real billing and Stripe integration
- workspace impersonation
- raw shell access
- arbitrary keeper-host filesystem access
- relay protocol changes for multi-tenancy

## Upgrade guidance

1. Run the database migration before pointing an existing deployment at the v1.2 Central binary.
2. Verify that the default workspace was created and that existing keepers and instances were backfilled into it.
3. Validate membership and capability checks with at least one non-admin human account.
4. Validate Progenitor and Keeper flows against staging before promoting a live deployment.

## Invariants to preserve

- instance IDs stay stable
- keeper IDs stay stable
- relay route assignments stay stable
- backup IDs and schedule IDs stay stable
- workspace scoping affects visibility and authorization, not the keeper or relay transport model
